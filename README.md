# LifeOS

LifeOS — персональная операционная система для повседневной жизни и работы:
задачи, входящие, расписание, сводка дня, проактивные наблюдения и ассистент,
который умеет читать данные и предлагать действия.

Ключевая идея: **ассистент — не отдельный чат, а часть рабочей среды**. Он видит
те же задачи и входящие, что и вы, а любые изменения предлагает подтвердить.

## Что уже работает

- **Задачи**: создание, фильтры, поиск, сортировка, пагинация, дедлайны
  (календарные и точные), теги, завершение/отмена/восстановление/перенос,
  optimistic locking через `If-Match`/`ETag`.
- **Входящие**: быстрый захват, разбор, конвертация в задачу с сохранением
  полного текста, удаление. Запись сразу относится к задаче, идее, заметке или
  цели: идея не превращается в задачу и возвращается в назначенный день.
- **Планирование времени**: у задачи есть оценка длительности и ожидаемый
  результат; планировщик считает свободные интервалы с учётом встреч и буферов
  и предлагает расстановку по срочности. План применяется целиком и атомарно,
  существующие договорённости не двигаются автоматически, а непоместившееся
  объясняется причиной. Перенос просроченного — отдельное предложение.
- **Напоминания и регулярные дела**: несколько напоминаний на задачу в зависимости
  от срочности и длительности, доставка через SSE и системное уведомление, отмена
  при завершении. Повторяющиеся задачи (`daily/weekly/monthly` с окном переноса)
  создают следующее вхождение при завершении и остаются в истории.
- **Сегодня**: статистика, фокус-задача, списки на сегодня и просроченных,
  быстрый ввод, панель наблюдений.
- **Календарь**: встречи и задачи в месячной сетке, панель дня, конфликты,
  источники «Работа / Встречи / Личное».
- **Документы**: загрузка DOCX, XLSX, XLS, PPTX, PDF, текстов и фотографий;
  конвертация в Markdown и прикрепление к сообщению. Ассистент читает документ
  инструментом и создаёт задачи уже в диалоге. Обработанный документ попадает в
  базу знаний, а извлечённые из него сведения связываются с источником.
- **Память и база знаний**: устойчивые сведения о пользователе и накопленные
  материалы живут отдельно от истории диалогов. У каждой записи есть источник,
  уверенность, категория, сущности и версия; факты, предположения и выводы
  различаются. Дубли объединяются по источникам, противоречия не перезаписываются
  молча, а попадают в очередь проверки. Ассистент получает личные сведения в
  каждом ходе, ищет материалы через `search_memory` и сохраняет новое
  инструментом `remember`. Раздел «Память» показывает всё это с источниками.
- **Ассистент**: streaming ответов и reasoning, выбор бесплатной модели, автоподтверждение, markdown, остановка генерации, диалоги, история, tool calling. Read-only инструменты
  выполняются сразу, мутации создают `pending_action` с превью и выполняются
  только после подтверждения. Приложенный документ передаётся модели целиком
  (или обрезается с подсказкой `read_document`), поэтому его не нужно просить заново.
- **Работа с машиной**: ассистент читает, создаёт, правит и удаляет файлы
  (`read_file`, `list_files`, `search_files`, `write_file`, `edit_file`,
  `delete_path`) и выполняет команды (`run_command`). Доступ по умолчанию — весь
  компьютер; `LIFEOS_TOOLS_ROOT` ограничивает его каталогом,
  `LIFEOS_TOOLS_SHELL=false` отключает оболочку.
- **Устойчивость провайдера**: сетевые сбои, `429` и `5xx` не роняют сообщение —
  запрос повторяется с backoff, затем ход переходит на другую модель (в интерфейсе
  видно «повторяю запрос» / «переключаюсь на другую модель»); повторная отправка
  после обрыва не дублирует сообщение пользователя.
- **Проактивность**: просрочки, дедлайны сегодня, перегрузка дня, backlog
  входящих, задачи без срока, совпадающие дедлайны. Наблюдения можно скрыть или
  отложить; повторные уведомления не спамят. Детекторы сопоставляют данные
  между собой: дедлайн, попавший на встречу, день, занятый встречами, важный
  срок завтра, свободное окно сегодня, договорённости в памяти без движения и
  цели, у которых срок приближается быстрее, чем движется работа.
- **Инициатива LifeOS**: когда наблюдение действительно стоит обращения,
  LifeOS сам начинает диалог в главном чате — с причиной и предлагаемым
  действием. Врата сдерживают инициативу: тихие часы, идущая встреча, пауза
  между обращениями, откат по видам, которые пользователь раз за разом
  отклоняет. Реакция фиксируется: ответ в чате, «принято», «не сейчас» или
  «скрыть».
- **Realtime**: SSE-поток `task.*`, `inbox.*`, `assistant.*`, `pending_action.*`,
  `insight.detected`, `outreach.created`, `memory.*` с replay по `Last-Event-ID`.
- **MCP**: tools-only сервер поверх Streamable HTTP; по умолчанию read-only.
- **Настройки и поиск**: JSON key-value настройки, общий поиск по задачам и
  входящим.
- **Данные**: SQLite, миграции goose, WAL, атомарные task + audit event.

## Архитектура

Modular monolith на Go со встроенным SvelteKit-фронтендом:

```
Transport (HTTP, SSE, MCP) → Application → Domain
                 ↑
          Infrastructure (SQLite)
                 ↑
            Agent Runtime (LLM + tools)
```

- `internal/domain` — Task, InboxItem, TaskEvent, Conversation, Message,
  PendingAction, MemoryEntry; без внешних зависимостей.
- `internal/application` — use cases: tasks, inbox, summary, assistant,
  proactive, planning, documents, completion, memory, search, settings.
- `internal/infrastructure/sqlite` — репозитории, Unit of Work, миграции.
- `internal/transport` — REST/SSE, MCP-адаптер.
- `internal/agent` — OpenAI-совместимый провайдер и реестр инструментов.
- `web` — SvelteKit SPA, встраивается в Go-бинарник.

Подробности: [ARCHITECTURE.md](ARCHITECTURE.md), [DATA_MODEL.md](DATA_MODEL.md),
[API_CONTRACT.md](API_CONTRACT.md), [DECISIONS.md](DECISIONS.md),
[DEPLOYMENT.md](DEPLOYMENT.md), [MCP.md](MCP.md), [ROADMAP.md](ROADMAP.md).

## Быстрый старт

Требования: Go 1.27.3, Node.js 20+, npm 10+.

```bash
cp .env.example .env
# заполните LIFEOS_LLM_API_KEY, если нужен ассистент

# 1. Собрать фронтенд
cd web && npm ci && npm run build && cd ..

# 2. Встроить сборку и запустить
rm -rf internal/web/dist/build && cp -r web/build internal/web/dist/build
go run ./cmd/lifeos
```

Откройте http://127.0.0.1:8787 — данные лежат в `./data/lifeos.db`.

Для разработки фронтенда:

```bash
cd web && npm run dev     # http://localhost:5173, API проксируется на :8787
```

## Конфигурация

Все переменные — в [.env.example](.env.example). Основные:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `LIFEOS_LISTEN_ADDR` | `127.0.0.1:8787` | Адрес HTTP-сервера |
| `LIFEOS_DATA_DIR` | `./data` | Директория SQLite |
| `LIFEOS_TIMEZONE` | `Europe/Moscow` | Часовой пояс по умолчанию |
| `LIFEOS_LLM_PROVIDER` | `openrouter` | `openrouter` или `ollama` |
| `LIFEOS_LLM_BASE_URL` | `https://openrouter.ai/api/v1` | OpenAI-совместимый endpoint |
| `LIFEOS_LLM_API_KEY` | — | Ключ провайдера |
| `LIFEOS_LLM_MODEL` | `openai/gpt-4o-mini` | Модель |
| `LIFEOS_MCP_ENABLED` | `false` | Включить MCP |
| `LIFEOS_MCP_ALLOW_WRITES` | `false` | Разрешить мутации через MCP |

Без ключа (и без `LIFEOS_LLM_PROVIDER=ollama`) ассистент отвечает `503`, а
остальные экраны работают.

```bash
go vet ./...
```

## Ограничения текущей версии

- Один пользователь, без авторизации; доступ рассчитан на локальную сеть или
  Tailscale.
- Ассистент синхронный: ответ приходит в рамках запроса, без стриминга токенов.
- MCP по умолчанию read-only; мутации включаются явно.
- Поиск по входящим выполняется сканированием (Unicode case folding); при
  росте объёма данных потребуется индекс. Поиск по памяти и базе знаний
  использует `FTS5`.
- Извлечение фактов для памяти требует модели `LIFEOS_DOC_LLM_*`. Без неё память
  остаётся ручной, а документы всё равно индексируются целиком.
- Внешние интеграции (почта, календарь, файлы, голос) пока не подключены —
  архитектура готова к их добавлению как новых инструментов и модулей.
